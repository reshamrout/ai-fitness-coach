# API Design Checklist

- [ ] Endpoint models a clear resource or operation.
- [ ] Path naming is consistent with nearby endpoints.
- [ ] HTTP method matches the operation.
- [ ] Success status code is correct.
- [ ] Error status codes are defined.
- [ ] Error response shape is consistent.
- [ ] Request body, query, params, and headers are validated.
- [ ] List endpoints define pagination.
- [ ] Filtering and sorting behavior is documented.
- [ ] Authentication and authorization requirements are clear.
- [ ] Sensitive fields are excluded from responses.
- [ ] Backwards compatibility is considered.
